# Sprint Illustrations — Design Spec

Date: 2026-09-28
Status: Approved design, pending spec review
Targets: PHP 8.1+, WordPress 6.4+, Elementor 3.x and 4.x (classic widget API)

## 1. Purpose

Generate flat-style illustration SVGs (hero sections, featured images, feature blocks, empty states, service cards) by composing pre-made SVG pieces into scene templates, recoloured to the site palette. Output is deterministic for a given seed, inline, sanitized, and needs no front-end JavaScript. The plugin works fully without an API key; AI selection is an optional layer.

## 2. Decisions

| Topic | Decision |
|---|---|
| Composition runtime | A single PHP composer. The React builder previews via REST (debounced ~150 ms). No JS port. |
| Saved illustration | A private CPT `si_illustration` stores the SceneSpec and re-renders live. Media Library export is a separate action (SVG, and optionally PNG). |
| Sanitizer | `enshrined/svg-sanitize`, prefixed with Strauss (`SprintIllustrations\Vendor\`), wrapped in our own pass. |
| Cache | Files in `uploads/sprint-illustrations/cache/`, keyed by a hash that includes version counters. |
| Anchors for imported pieces | Marker elements in the SVG (`id="anchor-<name>"`), read and then removed by the manifest builder. |
| Character style | Faceless geometric figures: simple shapes, oversized limbs, no facial features, optional outline slot. |
| Elementor | A classic `Widget_Base` widget, which runs on 3.x and 4.x. The palette import reads Kit globals, then Elementor 4 colour Variables when present. |

## 4. Pieces and colour slots

### 4.1 SVG authoring rules

- Each piece is a standalone SVG with a `viewBox`. It uses no `<style>` blocks, `<script>`, `<image>`, `<foreignObject>` or external references.
- Colour comes only from slot classes:
  - `slot-<name>` sets `fill` for `primary`, `secondary`, `accent`, `neutral`, `skin`, `hair`, `background`.
  - `slot-outline` sets `stroke` (outline is always a stroke). Outline strokes are authored at `stroke-width="2"` in piece units with `vector-effect="non-scaling-stroke"`, so line weight stays consistent across scaled pieces.
  - Shade variants: `slot-<name>-light` and `slot-<name>-dark` (for example `slot-primary-dark`).
  - Stroke variant for any slot: `slot-stroke-<name>`.
- Hard-coded colours are allowed only for `none`/`transparent`. The manifest builder warns about any other literal colour.
- Skin tones: `slot-skin` resolves per character instance from `palette.skin[]`, chosen by the seed.

### 4.2 Manifest entry (`assets/manifest.json`)

```json
{
  "version": 3,
  "pieces": [{
    "id": "char-alex-sit-laptop",
    "label": "Alex, sitting with laptop",
    "category": "characters",
    "file": "characters/alex-sit-laptop.svg",
    "tags": ["work", "laptop", "sitting", "tech"],
    "viewBox": [0, 0, 240, 320],
    "size": [240, 320],
    "z": 30,
    "anchors": { "hand-right": [168, 190], "ground": [120, 318] },
    "accepts": { "hand-right": "handheld" },
    "mounts": {},
    "slots": ["primary", "secondary", "skin", "hair", "outline", "neutral"],
    "hash": "3f2a…"
  }]
}
```

Attachment model:
- A parent anchor lists the attachment type it `accepts`: `handheld`, `surface` or `top`.
- A child piece lists `mounts`: the anchor on itself that aligns to that type. For example, a phone has `"mounts": {"handheld": "grip"}` and `"anchors": {"grip": [20, 44]}`, and a plant has `"mounts": {"surface": "base"}`.
- The resolver only attaches a child whose `mounts` covers the parent anchor's type. A plant can never be put in a hand.

`version` increments on every build and feeds cache invalidation.

### 4.3 Library locations

- Bundled pieces: `assets/pieces/` with `assets/manifest.json`.
- User pieces: `uploads/sprint-illustrations/pieces/` with their own `manifest.json`, so they survive plugin updates.
- The `sprint_illustrations_library_paths` filter adds more paths.
- `Manifest` merges all sources. IDs must be globally unique; a duplicate ID is a load error that is logged, and the later entry is skipped.

## 5. Templates (`assets/templates/*.json`)

```json
{
  "id": "hero-left-character",
  "label": "Hero – character left",
  "canvas": [800, 600],
  "tags": ["hero", "work", "person"],
  "slots": [
    { "name": "bg", "category": "backgrounds", "box": [80, 40, 640, 520], "fit": "contain", "z": 0, "required": true },
    { "name": "subject", "category": "characters", "box": [120, 140, 300, 420],
      "fit": "contain", "align": "bottom", "scale": [0.9, 1.1], "z": 30, "required": true },
    { "name": "prop", "category": "objects", "attach": { "to": "subject", "anchor": "hand-right" } },
    { "name": "side", "category": "objects", "box": [480, 300, 200, 200], "align": "bottom",
      "prefer": ["plant", "chart"], "z": 20 },
    { "name": "decor", "category": "decor", "box": [0, 0, 800, 600], "count": [2, 4], "scatter": true, "z": 5 }
  ]
}
```

- Placement is either `box` (x, y, w, h in canvas units, plus `fit` and `align`) or `attach` (to another slot's anchor). An attached slot renders directly above its parent unless it sets `"behind": true`.
- `scale` is a range; the seed picks a value within it.
- `count` plus `scatter`: the seed places N pieces inside the box with a minimum spacing rule (reject-and-retry, bounded to 20 attempts per item).
- Slots are optional unless `required`. If a required slot can't be filled, that's a validation error.
- `prefer` adds a score bonus to pieces with those tags. `require_tags` filters the candidate pool.

Starter templates: `hero-left-character`, `hero-right-character`, `centered-object-with-decor`, `two-people-collaborating`, `empty-state`, `feature-card-object`.

## 6. SceneSpec

The single input shape for the builder, the CPT, shortcode/block/widget parameters and AI output:

```json
{
  "template": "hero-left-character",
  "seed": 1234,
  "palette": "preset:ocean",
  "keywords": ["remote", "team"],
  "picks": { "subject": "char-alex-sit-laptop", "decor": ["decor-dots", "decor-sparkle"] },
  "title": "Person working on a laptop",
  "decorative": false
}
```

- `palette` is `"site"`, `"preset:<id>"` or an inline palette object.
- `picks` is partial. The seed resolves unpicked slots.
- If `template` is missing and `keywords` are present, the Selector chooses the template.
- `SceneSpec::fromArray()` validates types. `SceneResolver` validates the spec against the manifest (unknown IDs, a wrong category, incompatible attachments) and returns a `ValidationResult`. Invalid picks are dropped and re-resolved, with a warning. The spec is rejected only when a required slot can't be filled.

## 7. Composer pipeline

`Composer::compose(SceneSpec, Palette): ComposedSvg`

1. **SceneResolver**: template, manifest and `Seed` produce a concrete list of `Placement` objects (piece, slot, transform inputs, z).
2. **Seed**: a mulberry32 PRNG seeded from `crc32(seed . '|' . template)`. Draws are in a fixed order: slot order, then count, then pieces, then scale, then scatter. Identical on every PHP version and platform.
3. **Placement / Transform**: compute `translate`/`scale` from the box, fit and align, or from parent anchor minus child mount anchor. Values are rounded to 2 decimals for stable output.
4. **SvgDocument**: load each piece's inner markup through DOMDocument (parsed once per request and memoized) and wrap it in `<g transform="…">` inside a nested `<svg viewBox>` or a `<g>` with a clip where needed.
5. **Recolorer**: replace `slot-*` classes with explicit `fill`/`stroke` attributes from the resolved palette. The slot classes are removed, and the output carries no `<style>`, so it's safe for inline use and themes can't bleed in.
6. **IdScoper**: rewrite every `id` and every `url(#…)`, `href="#…"` and `xlink:href="#…"` reference to `__SIID__-<n>`. The Renderer replaces `__SIID__` with `si-<hash8>-<instance>` at output time, using a per-request counter. Cached markup stays shared, and IDs stay unique even when the same illustration appears twice on a page.
7. **Sanitizer**: see §10.
8. **Wrap**: `<svg xmlns viewBox="0 0 W H" role="img" aria-labelledby="…-t …-d">` with `<title>` (from `spec.title` or the template label) and `<desc>` (generated from the piece labels). If `decorative` is set, output `aria-hidden="true"` with no title/desc. Width/height attributes are omitted; the wrapper CSS sizes it.

**Error handling:** the composer throws `CompositionException` (a missing piece file, an unparsable SVG, an unfillable required slot). The Renderer catches it and outputs nothing to visitors, with an HTML comment and a `WP_DEBUG` log line. Editors see a notice in the block or widget preview.

## 8. Palette system

- `Palette` value object: `primary`, `secondary`, `accent`, `neutral`, `background`, `outline`, `skin[]`, `hair[]`.
- `Tints` derives `-light` and `-dark` for each colour slot by shifting lightness in HSL (±18%, clamped). It flags pairs whose contrast falls below 1.3:1 against `background` (a builder warning only).
- `PaletteRepository`: presets from `assets/palettes/presets.json` (6 presets), the site palette from the `sprint_illustrations_palette` option, and inline palettes.
- `ElementorColors`: when Elementor is active, read the active Kit's `system_colors` and `custom_colors` through `Plugin::$instance->kits_manager`. On Elementor 4, also read colour Variables. **Where Elementor 4 stores these must be confirmed against the installed 4.2 source during phase 2 before it's implemented.** The import is a one-shot mapping in settings, with a UI to choose which Elementor colour fills which slot, plus an optional "keep synced" toggle that re-reads on `elementor/editor/after_save` of the Kit.
- Any palette save increments `CacheVersion::palette`.

## 9. Caching

- `SvgCache` stores `uploads/sprint-illustrations/cache/<sha1>.svg`.
- Key: `sha1(json(normalized spec) . resolved palette hash . manifest version . plugin version)`. Normalizing sorts keys so equivalent specs share a key.
- Invalidation happens by construction, because a change to the manifest, palette or plugin version gives a new key. Old files are removed by a daily cron that deletes files older than 30 days and not accessed recently, and by a "Purge cache" button in settings.
- An `index.php` and `.htaccess` deny rule sit in the cache directory. Files are only read server-side and are never linked.
- If the cache directory isn't writable, the plugin falls back to a non-persistent object cache for the request and shows an admin notice.

## 10. Security

- **Sanitizer:** the prefixed `enshrined/svg-sanitize` with a tightened allowlist (no `<script>`, `<foreignObject>`, `<image>`, `<use>` to external targets, `<a>`, `<animate*>`, or `<set>`). An extra pass removes all `on*` attributes, any `href` or `xlink:href` not starting with `#`, any `url(` not pointing at `url(#`, `style` attributes containing `url(` or `expression`, and processing instructions and DOCTYPEs. It runs on piece load, on compose output, on Media export, and on every Renderer output (cheap, and it covers cached files that may have been tampered with).
- **REST** (namespace `sprint-illustrations/v1`), all with nonce plus capability:
  - `POST /compose`, `GET /library`: `edit_posts`
  - `GET|POST|PUT|DELETE /illustrations`: `edit_posts` (own posts); editing others' posts uses the standard CPT caps mapped to post caps
  - `POST /media/svg` and `POST /media/png`: `upload_files`
  - `/settings` and `/ai/suggest`: `manage_options` and `edit_posts` respectively
- PNG upload: validated as `image/png` by `wp_check_filetype_and_ext` and `getimagesize`, size-capped at 5 MB.
- **API key:** `SecretStore` encrypts with sodium `crypto_secretbox`, using a key derived from `wp_salt('auth')`. The `SPRINT_ILLUSTRATIONS_API_KEY` constant overrides it. The key is never localized, never returned by REST (only `has_key: true`), and never logged.
- All admin output is escaped. Shortcode and block attributes are sanitized through `SceneSpec::fromArray()` before use.

## 11. Selection

### 11.1 RulesSelector (default)

1. Tokenize the title, excerpt or keywords: lowercase, strip tags and stopwords, crude plural stripping.
2. Expand tokens with `synonyms.json` (for example `team → people, collaboration`, `money → chart, finance`).
3. Template score = 3 × (template tag hits) + a bonus when the template's required categories have matching pieces. Ties are broken by the seed.
4. Per slot, piece score = 2 × tag hits + `prefer` bonus. Candidates are pieces with score ≥ max − 1, and the seed picks among them, so there's variety without drifting off-topic. With zero hits, the seed picks from the whole pool.

Output: a SceneSpec with `picks` filled. The same input and seed always give the same spec.

### 11.2 AiSelector (optional, phase 5)

- Enabled only when a key exists and the setting is on.
- Sends the content, plus the manifest (IDs, categories, tags, anchor types only) and the template list (IDs, tags, slot names and categories), to the Anthropic Messages API through `wp_remote_post` with a 20 s timeout. It requests JSON output that matches the SceneSpec schema.
- The response goes through `SceneSpec::fromArray()` and `SceneResolver` validation. Any failure (HTTP, parsing, validation) falls back to RulesSelector and logs the reason.
- **AI calls never happen during a visitor's page render.** They run only from the builder and from editor-time actions: "Suggest from content" in the block, widget or builder. The resulting spec is persisted in block attributes, widget settings or the CPT.
- The model ID is a setting. The default is chosen in phase 5 against current Anthropic docs (via the claude-api reference), not guessed now.

## 12. Storage

- The `si_illustration` CPT: `public => false`, `show_ui => false` (the builder is the UI), `show_in_rest => false` (our own controller), `capability_type => 'post'`. The spec is stored in `_si_spec` post meta (JSON). The title is the post title.
- `MediaExporter`: the SVG attachment is created with `wp_insert_attachment` from the sanitized markup, written with `wp_upload_bits`. It doesn't require enabling SVG uploads site-wide. It stores `_si_source_illustration` meta. The PNG is rendered client-side (canvas at 1200×630 or 2× canvas size, user choice) and uploaded to `/media/png`, where it's attached to the same source.

## 13. Admin UI

- Top-level menu **Sprint Illustrations**: Builder (`edit_posts`), Library (a read-only piece and template browser, phase 3), Settings (`manage_options`), Test page (phase 1 only; kept behind `WP_DEBUG` afterwards).
- **Builder** (React, `@wordpress/components`, `@wordpress/api-fetch`, `@wordpress/data` store):
  - Left rail: template picker (thumbnail cards), slot list. Selecting a slot opens a filterable piece grid (search by tag, filtered by the slot's category and by compatibility for attached slots).
  - Centre: the preview stage on a neutral canvas with a size toggle (16:9, 4:3, 1:1).
  - Right: palette (site, presets, custom with colour pickers and tint preview), the seed with Shuffle (new random seed) and lock-per-slot (a locked slot keeps its pick across shuffles), title/alt, and the decorative toggle.
  - Actions: Save (CPT), Save to Media (SVG), Export PNG, Copy shortcode.
  - Visual direction (the frontend-design pass happens in phase 3): native WP admin look, with the stage as the hero. Generous canvas, subtle dot grid, crisp slot highlighting on hover. No gratuitous chrome.

## 14. Placement surfaces

All three call `Render\Renderer::render(array $args): string`.

- **Block** `sprint-illustrations/illustration`: `block.json`, apiVersion 3, server-rendered with `render.php`, `ServerSideRender` in the editor. Attributes: `illustrationId` or `template`, `keywords`, `seed`, `palette`, `picks`, `title`, `decorative`. Sidebar controls: pick a saved illustration or generate inline, Shuffle, Suggest from post (uses the post title and excerpt).
- **Shortcode**: `[sprint_illustration id="12"]` or `[sprint_illustration template="hero-left-character" keywords="team,remote" seed="42" palette="preset:ocean"]`.
- **Elementor widget**: classic `Widget_Base`, registered on `elementor/widgets/register`, with the same controls as the block (select a saved illustration, or template, keywords, seed and palette controls). Rendering happens server-side in both `render()` and the editor preview (no `content_template()`), so the preview matches the front end.
- Wrapper: `<figure class="si-illustration si-template-{id}">` with a small enqueued CSS file (about 10 lines, `max-width:100%` and aspect ratio). There's no JavaScript on the front end.

## 15. Manifest builder and import flow

- Run with `php bin/build-manifest.php [--source=<dir>] [--target=<dir>] [--non-interactive]` or `wp sprint-illustrations build-manifest` (it defaults to user pieces in uploads).
- Flow:
  1. Drop SVGs into `<target>/_inbox/<category>/`.
  2. The builder parses each file, detects `slot-*` classes, and reads `id="anchor-*"` markers (circle `cx`/`cy`, or rect centre, or ellipse centre, all resolved through the marker's ancestor transforms). It removes the markers.
  3. It warns about literal colours, disallowed elements and non-slot strokes, then sanitizes.
  4. It prompts for tags, z, `accepts` for each anchor, and `mounts`. Existing entries prefill the answers.
  5. It writes the cleaned SVG to `<target>/<category>/`, updates `manifest.json` (hash, version + 1), and moves the original to `_inbox/_processed/`.
- `--non-interactive` uses the filename for tags (`plant-tall` becomes `plant, tall`) and defaults for the rest. Useful for batch imports.
- The steps are documented in `docs/importing-pieces.md`, including the Figma/Illustrator export settings (layer names exported as IDs, outline strokes at 2px).

## 16. Starter asset pack

Original work in a geometric flat style: faceless characters, rounded rectangles and circles, 2px outline, limited slots.

- **Characters (4 × 2–3 poses):** standing-pointing, sitting-laptop, holding-object, waving. Varied builds and hair shapes.
- **Objects (10):** laptop, phone, plant, chart board, coffee cup, documents, chat bubble, lightbulb, gear, rocket.
- **Backgrounds (3):** blob, circle, soft shapes.
- **Decor (6+):** dot grid, sparkle, plus, squiggle line, ring, confetti.

All pieces are drawn from scratch in code for this project, not traced from anything.

## 17. Testing

- **Unit (plain PHPUnit, no WP):**
  - Seed determinism (golden hashes per seed and template)
  - Placement maths
  - Recolorer mapping
  - IdScoper, including references
  - Sanitizer, against an attack corpus (script, onload, xlink external, foreignObject, style url(), data: URIs, entity expansion)
  - RulesSelector scoring
  - SceneSpec validation
  - Manifest merge and duplicate handling
  - Marker anchor extraction with transforms
- **Integration (wp-env or the Local site through WP-CLI in the Local site shell):**
  - REST permission matrix (anonymous, subscriber, author, admin)
  - Renderer output for all three surfaces
  - Cache hit and miss
  - Media export
- **Golden visual check:** the admin Test page renders every template × 4 seeds × 2 palettes for eyeballing.
- Coding standards: PHPCS with WPCS plus PHPCompatibilityWP (8.1). ESLint and Stylelint through `wp-scripts`.

## 18. Build phases

1. **Core**: scaffold (Composer, Strauss, PHPCS, PHPUnit), manifest and template schemas, starter pack, Library + Compose + Sanitizer, a default palette (hard-coded), manifest builder, Test page, WP-CLI `compose`.
2. **Palette and cache**: Palette, Tints, presets, Settings page, ElementorColors (3.x Kit and 4.x Variables), SvgCache + CacheVersion + cron + purge.
3. **Builder**: REST controllers, CPT, React builder, Media export (SVG and PNG), Library browser.
4. **Placement**: Renderer, block, shortcode, Elementor widget.
5. **AI**: SecretStore, AiSelector, "Suggest" actions in the builder, block and widget.

Each phase ends with test instructions and a list of open questions.

## 19. Out of scope (YAGNI)

- Animation, and editing individual paths in the browser.
- Free-form drag positioning in the builder. Positions come from templates. A per-slot nudge may come later if needed.
- Multisite-specific settings beyond per-site options.
- Selling or syncing piece packs remotely.
